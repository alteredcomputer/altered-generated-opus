# Plans

The execution layer under `macro-plan.md`. Each file in this folder is an end-to-end, top-to-bottom
plan for one workstream, written so that a fresh agent with no chat memory can execute it from the
file alone. The owner starts one Cursor chat per plan and says **next** or **finish** (D071). This
file carries the order and the status, so that word is enough.

## Protocol for a fresh agent

1. Read `AGENTS.md`, then `knowledge/state.md`, then this file. Do not skip the operating
   contract; every plan assumes it.
2. Find your plan:
   - **"next"** means: take the first plan in the order below whose status is `ready`.
   - **"finish"** means: take the plan whose status is `in progress`. If more than one is in
     progress, take the lowest number and say so in chat.
   - A plan named explicitly wins over both.
3. Start every session from a fresh `origin/main` (`git fetch origin main && git checkout main &&
   git reset --hard origin/main`), then branch as `cursor/plan-NN-<slug>-<suffix>`.
4. Before writing code: set the plan's status to `in progress` here and in the plan file, and add
   or update the plan's feature graph nodes as `planned` or `in-progress`.
5. Work the steps in order. Each step ends in a commit. Commit messages name the plan number.
6. When you hit something meaningful - a wrong assumption, a missing credential, a decision the
   plan did not anticipate - append a dated entry to the plan's **Agent notes** section. If it
   blocks you, set status to `blocked`, name the blocker here in the table, update `state.md`,
   and stop with a question in chat that carries options and a recommendation. Never guess past
   an open question.
7. Before merging: quality pass, the itemised security pass from `AGENTS.md`, feature graph
   reconciliation, `pnpm check`, `pnpm build`. Then update `state.md`, set the status to `done` or
   back to `ready` with a note, merge to `main`, push.
8. A plan is done when the owner can do the thing named under **Outcome** from his phone, not
   when the code compiles.

## Shared technical decisions

Six agents in six chats have to produce one codebase. These are the choices they share. Deviating
is allowed when a plan's design says so, and must be recorded in that plan's notes.

- **Runtime:** Next.js 16 app router, React 19, TypeScript 5.9, pnpm workspaces, Turborepo. One
  deployed application (D050).
- **Effect v4** for services, configuration, typed errors, and logging (D032). Wrap popular
  libraries at the edges rather than replacing them (D014). Every new environment variable is
  declared once in `packages/core/src/config.ts` and documented in `.env.example`.
- **Database:** Neon Postgres through Drizzle ORM with the Neon serverless HTTP driver. Schema
  lives in a `packages/db` workspace package; migrations are generated by `drizzle-kit` and
  committed. Every table that holds a person's data carries an owner or scope column, and every
  read filters on it at the query.
- **Auth:** Better Auth with the email OTP plugin, codes delivered by Resend (D046). One operator
  allowlist, from configuration, fail-closed: an empty allowlist admits nobody.
- **AI:** AI SDK v7 through the OpenRouter provider (D014). Model names are settings, not
  constants (D009). Every model call logs tokens and cost.
- **Interface:** the dashboard uses shadcn/ui on Tailwind v4 under its own route group and layout,
  keeping the public site's CSS-module visual system untouched. Berkeley Mono everywhere, the
  existing neutral ramp and single accent, follows the system theme, small radius on controls.
  Mobile-first: designed at 390px wide and verified there before anything else.
- **Tests:** Vitest. Pure logic gets unit tests; anything with a fail-closed rule gets a test for
  the empty case. `pnpm check` grows a `check:tests` step in plan 01.
- **Settings store:** a `settings` table of typed keys, read through one module, with the key
  names declared in the feature graph's `controls` dataset. Anything a human might want to change
  lives there (D009).
- **Kill switches:** `OUTBOUND_ENABLED` is the master, and each integration has its own boolean
  in the settings store that defaults to off. A live write checks both.
- **Logging:** through `@opus/core/runtime`. Console is a lint error. Every model call, every
  external write, and every operator action produces a structured log line with a correlation id.
- **Copy:** hyphens only, no em dashes, and no claim that does not trace to `decisions.md`.
